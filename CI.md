# Автоматическая сборка и черновики релизов

[Открыть Android APK в GitHub Actions](https://github.com/holodilow-sudo/arseniyMove/actions/workflows/android.yml).

После изменений приложения в main GitHub запускает проверки, собирает и подписывает APK прежним ключом, затем создаёт **Draft** в Releases. В черновике находятся APK, контрольные суммы, точные исходники, инструкция и отчёт проверки. Если черновик этой версии уже существует, его файлы обновляются. Опубликованные релизы не перезаписываются.

**Автоматической публикации нет.** Черновик виден владельцу репозитория и не появляется в обновлениях на телефоне. Публиковать его можно только после согласования владельцем.

## Выпуск обновления

1. Сохраните доработки в main и дождитесь успешной сборки Android APK.
2. Откройте [Releases](https://github.com/holodilow-sudo/arseniyMove/releases), выберите новый Draft. Проверьте описание и APK; сборка не заменяет проверку на реальном телефоне.
3. После согласования откройте редактирование черновика и нажмите **Publish release**, оставив обычный стабильный выпуск и Latest.

До шага 3 у Арсения остаётся прежняя опубликованная версия. После публикации приложение 1.0.12+ найдёт обновление при открытии или через «Настройки → Проверить обновления». Установку подтверждает Android. Для 1.0.11 и старее потребуется один раз установить новый APK вручную поверх старого.

Для ручного запуска: Actions → Android APK → Run workflow → ветка main. Поля версии и Android-кода можно оставить пустыми: скрипт выберет следующую patch-версию и больший versionCode относительно последнего опубликованного APK. Можно указать свои большие номера. Ручной запуск также создаёт только черновик.

Пока предыдущий черновик не опубликован, следующие сборки обновляют этот черновик. После его публикации следующая сборка создаст черновик следующей версии. Номера проставляются в рабочей копии сборки; точные исходники приложены к черновику, исходный коммит указан в verification.json. Исходный AndroidManifest.xml в main автоматически не изменяется.

Готовые файлы также доступны в Artifacts соответствующего запуска 14 дней. Pull request запускает только проверки без доступа к подписи. Изменения одной документации сборку не запускают; при необходимости используйте Run workflow.

## Закрытая подпись

Settings → Secrets and variables → Actions содержит два **Repository secrets**:

- ANDROID_KEYSTORE_BASE64 — существующий PKCS#12 в base64.
- ANDROID_KEYSTORE_PASSWORD — пароль хранилища и ключа.

Base64 — только формат передачи: конфиденциальность обеспечивает хранение в GitHub Secrets. Значения не записываются в репозиторий, исходники, артефакты или workflow. Только шаг сборки получает эти Secrets. Keystore временно восстанавливается в RUNNER_TEMP и удаляется в finally; пароль передаётся утилите подписи через окружение. Без Secrets сборка завершается ошибкой, новый ключ не создаётся.

Alias: arseniymove. Обязательный публичный отпечаток SHA-256 сертификата: e3b08b0560d6dda65322d7aa16a4c615bae87c4d3eac8929b3392c260d266b57. Он совпадает с прежними APK, поэтому обновление совместимо с установленным приложением.

Доступ на запись в репозиторий выдавайте только доверенным разработчикам: они могут изменить способ использования Secrets. Сохраните локальную приватную резервную копию android/.signing; GitHub не показывает сохранённые значения обратно.

## Среда

GitHub-hosted Windows 2022, Temurin JDK 17, Android Platform 35, Build Tools 35.0.0. Официальные Actions закреплены полными commit SHA. Проверки и подпись имеют только чтение репозитория; отдельная job создания черновика получает contents: write. На телефоне вход в GitHub и ключи не требуются.
