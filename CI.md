# Автоматическая сборка APK

Workflow: **Actions → Android APK**.

После изменений приложения в `main` GitHub автоматически запускает проверки и собирает подписанный APK. Готовые файлы доступны в Artifacts соответствующего запуска 14 дней. Pull request запускает только проверки, без доступа к подписи.

## Выпустить обновление

1. Сохраните доработки в `main`.
2. Откройте Actions → Android APK → Run workflow, выберите ветку `main`.
3. Введите новую версию, например `1.0.15`, и больший Android-код, например `16`. Поля можно оставить пустыми, если нужные номера уже записаны в AndroidManifest.xml.
4. Включите **Опубликовать новое обновление в Releases** и запустите workflow.

Без этой галочки получится проверочная сборка в Artifacts, а обновление на телефоне не появится. С галочкой после проверок GitHub создаст стабильный Latest Release с APK, SHA-256, инструкцией и исходниками. Установленное приложение 1.0.12+ найдёт его при открытии или по кнопке проверки обновлений. Android всё равно запросит подтверждение установки.

Номер версии и versionCode должны превышать последний опубликованный выпуск. Повторная публикация под существующим номером запрещена. Номера проставляются в рабочей копии сборки; исходники с точными номерами приложены к релизу, исходный коммит записан в verification.json.

## Закрытая подпись

В Settings → Secrets and variables → Actions хранятся два **Repository secrets**:

- `ANDROID_KEYSTORE_BASE64` — существующий PKCS#12, закодированный base64.
- `ANDROID_KEYSTORE_PASSWORD` — его пароль (он же пароль ключа в этом PKCS#12).

Alias: `arseniymove`. Ожидаемый SHA-256 сертификата: `e3b08b0560d6dda65322d7aa16a4c615bae87c4d3eac8929b3392c260d266b57`. Это публичный отпечаток, не секрет.

Значения не записываются в репозиторий или workflow. Только шаг подписи получает Secrets. Keystore восстанавливается в RUNNER_TEMP и удаляется в finally; пароль передаётся подписывающей утилите через окружение. В артефакты включается только явный список выходных файлов. При отсутствии секрета новый ключ не создаётся. Сертификат готового APK обязан совпасть с прежними выпусками.

Доступ на запись в репозиторий выдавайте только доверенным разработчикам: изменение workflow может изменить способ использования Secrets. Сохраните локальную приватную резервную копию `android/.signing`; GitHub не показывает сохранённые значения секретов обратно.

## Среда сборки

GitHub-hosted `windows-2022`, Temurin JDK 17, Android Platform 35 и Build Tools 35.0.0. Действия GitHub закреплены полными commit SHA. Только отдельная job публикации получает `contents: write`; проверка и подпись работают с чтением репозитория. Никаких входов и ключей на телефоне нет.
